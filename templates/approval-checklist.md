# 승인 체크리스트 v1

v1 · 2회차 (2026-10-06)
오늘 바뀐 점:
- 테스트: "테스트가 충분하다" → 새 public 메서드마다 테스트 1건 이상(접근자 제외)
- 치명 · 범위: 치명은 4유형(비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립)으로 한정, 범위 밖 변경은 같은 파일 안의 import 정리만 허용
- 컨벤션: 계층 규칙 위반 · 빈 catch · System.out 은 반려, 네이밍과 그 밖의 CLAUDE.md 위반은 경고

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립 네 유형 중 하나에 해당하는 문제. 1건이라도 있으면 반려. 네 유형에 해당하지 않으면 경고로 적는다.
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 승인 · 반려에 영향을 주지 않는다. 이슈 목록에 남겨 수정을 요청한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 이번 변경으로 새로 생긴 public 메서드마다 그 메서드를 호출하는 테스트가 1건 이상 있다(getter · setter · 생성자 · record 접근자는 제외).
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않다. (비밀값 노출)
- [ ] 데이터를 지우거나 덮어쓰는 코드가 새로 생겼다면 요청에 그 내용이 명시돼 있다. (데이터 손실)
- [ ] 인증 · 권한 검사를 지우거나 건너뛰는 경로(검사 삭제, `permitAll` 추가, 검사 전 반환)가 새로 생기지 않았다. (인증 우회)
- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 없다(파라미터 바인딩 사용). (SQL 문자열 조립)

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 문장으로 설명되지 않는 변경 줄이 0줄이다. 단, 요청으로 설명되는 파일 안에서 import 를 추가 · 삭제 · 정렬한 줄은 예외다.
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.

## 4. 컨벤션 준수

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).
- [ ] Controller 파일에 `Repository` import 가 없고, Controller 에서 SQL 을 직접 실행하는 곳이 없다. (계층 규칙)
- [ ] Controller 에 `try`/`catch` 가 없다(예외는 `GlobalExceptionHandler` 가 매핑한다). (계층 규칙)
- [ ] 본문이 비어 있거나 주석만 있는 `catch` 블록이 없다. (빈 catch)
- [ ] `System.out` · `printStackTrace` · `console.log` 같은 임시 출력이 남아 있지 않다. (System.out)

위 네 항목 외의 위반(네이밍, `@ActiveProfiles` · 한국어 `@DisplayName` 누락, `<클래스>Test.java` 부재 등 그 밖의 CLAUDE.md 컨벤션)은 **경고**로 이슈 목록에 올리고 이 기준의 판정에는 쓰지 않는다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
