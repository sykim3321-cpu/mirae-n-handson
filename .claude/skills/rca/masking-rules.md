# RCA 리포트 마스킹 규칙

리포트(`docs/rca/<시나리오>.md`)를 저장하기 전에 아래 규칙을 본문 · 표 · 코드 블록 · 실행 명령 전체에 적용한다. 원본 로그는 건드리지 않는다.

## 1. 대상과 치환 형식

| 대상 | 예 (원본 형태) | 치환 | 비고 |
|---|---|---|---|
| IP — 구분이 필요 없음 | `10.20.3.41` | 뒤 두 자리 가림: `10.20.x.x` | 명령 예시의 DB 호스트 등 |
| IP — 구분이 필요함 | 같은 장애에서 서로 다른 단말 · 서버 | **역할 별칭**: `API-1` · `API-2`(upstream 서버), `교사단말A` · `교사단말B` …(클라이언트) | 아래 2절 |
| 이메일 | `kim@school.example` | `[EMAIL]` | 로그인 ID 로 쓰인 경우도 포함 |
| 학생 식별자 | `STU-10234`, 학생 이름 | `학생A` · `학생B` … | 같은 학생은 리포트 안에서 같은 별칭 |
| 토큰 · 세션 · API 키 | `Bearer eyJ...`, `JSESSIONID=...`, `?token=...` | `[TOKEN]` | 앞 몇 글자도 남기지 않는다 |
| 비밀번호 · 접속 문자열 | `-p<비밀번호>`, `jdbc:...password=...` | `[SECRET]` | 계정 이름(`readonly`)은 남겨도 된다 |

## 2. 역할 별칭 규칙

- 서로 다른 IP 가 서로 다른 행동을 해서 **구분해야 원인 설명이 되는 경우**(예: 어느 upstream 이 timed out 이고 어느 쪽이 connect failed 인지, 어느 단말이 먼저 반복 요청을 시작했는지)에만 쓴다.
- 서버는 `API-1`, `API-2` …, 클라이언트는 역할 + 알파벳(`교사단말A`, `교사단말B` …)으로 붙인다. 역할을 모르면 `단말A` 처럼 쓴다.
- 알파벳은 **로그에 처음 나온 순서**대로 붙인다. 같은 IP 는 리포트 전체에서 같은 별칭을 쓴다.
- 별칭과 실제 값의 대응은 작업 중 머릿속(대화 맥락)에만 두고 **파일로 남기지 않는다.**

## 3. 저장 전 확인

1. 아래 명령으로 남은 원본 값이 0건인지 확인한다. 걸리면 해당 줄을 고친 뒤 다시 돌린다.
   ```bash
   grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|STU-[0-9]+|Bearer [A-Za-z0-9._-]+|eyJ[A-Za-z0-9_-]{10,}|(password|passwd|pwd)=[^ ]+| -p[^ [`]+' docs/rca/<시나리오>.md
   ```
   - 버전 번호(`1.2.3.4` 형태)처럼 IP 가 아닌 것이 걸리면 사유를 확인하고 넘어간다.
2. 리포트 맨 끝에 적용 건수를 한 줄로 남긴다.
   `마스킹 적용: IP N건 · 이메일 N건 · 학생 식별자 N건 · 토큰 N건 · 비밀번호/접속 문자열 N건`

## 4. 하지 말 것

- 마스킹 대응표(원본 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본 리포트나 로그를 임시 폴더 · 스크래치 디렉터리에 복사해 두지 않는다. 마스킹은 저장할 리포트 내용에 바로 적용한다.
