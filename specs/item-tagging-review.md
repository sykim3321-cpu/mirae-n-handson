# 문항 태깅 검수 도구 — 요구사항 스펙

- 문서 상태: 초안 v0.1 (콘텐츠 운영팀 작성, 개발 검토 전)
- 대상: 백엔드 API. 화면은 이번 범위가 아니다.

## 1. 배경과 목적

문항 은행의 문항에는 성취기준 · 단원 · 난이도 태그가 붙는다. 지금은 등록자가 태그를 붙이면 바로 반영되는데, 잘못 붙은 태그 때문에 평가지 자동 구성에서 엉뚱한 문항이 뽑히는 일이 반복됐다.

이번에 만드는 도구는 태그가 반영되기 전에 **검수자가 확인하고 승인 · 반려하는 절차**를 API로 제공한다. 운영팀 화면(별도 과제)이 이 API를 호출한다.

## 2. 기능 요구사항

### 2.1 검수 대기 목록 조회

이번 개발의 핵심 기능이다. 검수자는 검수를 기다리는 문항의 목록을 조회한다.

- 한 행에 문항 하나: 문항 ID, 문항 요약(본문 앞부분), 태그 목록, 등록자, 검수 요청 시각
- 검수 요청 시각이 오래된 문항이 먼저 나온다
- 태그 종류(성취기준 · 단원 · 난이도)로 목록을 거를 수 있다

### 2.2 검수 요청

- 등록자는 자신이 등록한 문항에 태그를 붙이고 검수를 요청한다.
- 검수를 요청하면 문항은 **검수 대기** 상태가 된다.

### 2.3 승인과 반려

- 검수자는 검수 대기 문항을 **승인**하거나 **반려**한다.
- 반려할 때는 반려 사유를 적어야 한다.
- 승인된 문항의 태그는 문항 은행에 반영된 것으로 본다.

### 2.4 반려된 문항 수정

- 등록자는 반려된 문항의 반려 사유를 볼 수 있다.
- 등록자는 반려된 문항의 태그를 고칠 수 있다.

### 2.5 사용자와 역할

- 사용자는 **등록자** 역할, **검수자** 역할 중 하나 이상을 가진다. 한 사람이 두 역할을 모두 가질 수 있다.
- 검수자는 여러 명이다. 문항을 특정 검수자에게 배정하지 않는다. 검수자들은 같은 검수 대기 목록을 함께 보고, 목록에서 문항을 골라 검수한다.
- API는 요청마다 요청한 사용자가 누구인지 알 수 있어야 한다. 로그인 · 토큰 같은 인증 방식은 별도 과제이므로, 이번에는 요청에 사용자 ID가 함께 실려 온다고 보고 만든다.

## 3. 도메인 규칙

### 3.1 용어

| 용어 | 설명 |
|---|---|
| 문항 | 문항 은행의 문제 하나. 본문과 등록자가 있다 |
| 태그 | 문항에 붙는 분류. 종류는 성취기준 · 단원 · 난이도다 |
| 검수 | 검수자가 문항의 태그를 확인하고 승인 또는 반려하는 일 |

식별자는 문자열이다. 예: 문항 `Q1001`, 사용자 `writer-01`, `reviewer-01`.

### 3.2 문항 상태

문항은 아래 네 상태 중 하나다.

| 상태 | 뜻 |
|---|---|
| 작성 중 | 등록됐지만 아직 검수를 요청하지 않음. 태그가 하나도 없는 문항도 있다 |
| 검수 대기 | 검수를 요청했고 검수자의 판정을 기다림 |
| 승인 | 검수자가 승인함. 태그가 반영됨 |
| 반려 | 검수자가 반려함. 반려 사유가 있음 |

### 3.3 태그

- 한 문항에 같은 종류의 태그가 여러 개 붙을 수 있다(예: 성취기준 두 개).
- 난이도 태그의 값은 `상` · `중` · `하` 중 하나다.

## 4. 비기능 요구사항

- 응답은 JSON이다.
- 외부 DB나 외부 서비스 없이 시작 골격에 설정된 저장 방식으로 돈다.
- 검수 대기 문항은 많아야 수백 건으로 본다. 목록 조회는 빠르게 응답해야 한다.
- 검수가 몰리는 시기에는 검수자 여러 명이 같은 목록을 열어 두고 동시에 작업한다.

## 5. 수용 기준

- **5.1** 검수자가 검수 대기 목록을 조회하면 검수 대기 상태의 문항만 요청 시각이 오래된 순으로 정상적으로 반환된다. (2.1)
- **5.2** 태그 종류로 거르면 그 종류의 태그가 붙은 문항만 나온다. (2.1)
- **5.3** 등록자가 검수를 요청하면 문항이 검수 대기 목록에 나타난다. (2.2)
- **5.4** 검수자가 승인하면 문항은 승인 상태가 되고 검수 대기 목록에서 빠진다. (2.3)
- **5.5** 반려 사유 없이 반려하면 적절한 오류를 반환한다. (2.3)
- **5.6** 반려된 문항의 등록자는 반려 사유를 확인하고 태그를 고칠 수 있다. (2.4)
- **5.7** 검수자 역할이 없는 사용자는 승인 · 반려할 수 없다. (2.5)
- **5.8** 존재하지 않는 문항을 승인 · 반려하면 적절한 오류를 반환한다. (2.3)

## 6. 범위 밖

- 태그 자동 추천
- 문항 본문의 작성 · 수정
- 승인된 태그를 실제 문항 은행 서비스에 전송하는 연동
- 알림(메일 · 메신저)
- 로그인 · 토큰 등 인증 방식 (2.5의 "요청에 사용자 ID가 실려 온다"로 대신한다)
